# MoonForge RE Workbench

**Cross-format binary evidence, release diff, and CI policy gates — in pure MoonBit.**

MoonForge turns PE / ELF / Mach-O / Info.plist / WASM artifacts into a normalized, provenance-carrying fact model. It answers three questions that single-file parsers do not answer together:

1. **What is in this artifact?** Format, hash, sections, symbols, imports, exports, bundle identity, WASM sections.
2. **What changed between two builds?** Deterministic added / removed / changed facts with byte locations.
3. **Should this release pass?** Declarative baseline-relative policy gates with JSON and SARIF output.

The same MoonBit core powers native CLIs and an offline WASM browser workbench. No backend, no FFI, no network at analysis time.

> This project is unrelated to `Lyhdsba/moonforge`, an incremental build-task runner. Mooncakes namespaces packages by author; MoonForge RE Workbench is `NaIWaniubi/moonforge`.

## Quick start

```bash
moon install
moon check --deny-warn
moon test -j 1

# Inventory a corpus
moon run cmd/main -- scan examples --out manifest.json

# PE import-slot -> call-site evidence
moon run cmd/main -- xref examples/notepad.exe --out xref.json

# Search extracted strings across a corpus
moon run cmd/main -- search examples HeapAlloc

# Compare two canonical fact sets
moon run cmd/diff -- fixtures_breadth/old-facts.json fixtures_breadth/new-facts.json

# Enforce a release policy (exit 0 pass / 1 violation / 2 error)
moon run cmd/gate -- fixtures_breadth/old-facts.json fixtures_breadth/new-facts.json fixtures_breadth/policy.json

# Bundle and WASM breadth tools
moon run cmd/bundle -- path/to/Mach-O path/to/Info.plist
moon run cmd/wasmcheck -- path/to/module.wasm
```

## Browser workbench

```bash
bash web/build.sh
cd web
python -m http.server 8080
```

Open `http://127.0.0.1:8080`, drop one or more artifacts, and inspect:

- per-artifact structure and SHA-256;
- section-aware, byte-derived xref v2 ledger;
- normalized old/new diff;
- Mach-O + Info.plist bundle profile;
- WASM section report;
- cross-file string search;
- raw canonical JSON and report export.

The multi-artifact protocol is versioned as `moonforge-v2`; the legacy single-file protocol remains supported.

## Why this is not “another parser wrapper”

Parsers already exist. MoonForge's contribution is the **evidence and decision layer**:

- **Evidence envelope** — every finding carries artifact hash, parser/dependency version, status, and byte location.
- **xref v2** — executable sections are decoded independently; `E8 rel32` and `FF 15 rip-rel32` targets are derived from instruction bytes, not display strings; the call ledger is complete and auditable.
- **Canonical diff** — PE / ELF / Mach-O / plist / WASM facts are normalized into one deterministic schema.
- **Policy gate** — rules such as “no new kernel32 import” produce explainable JSON/SARIF and stable exit codes.
- **One core, two runtimes** — native and WASM outputs are generated by the same MoonBit code.

| Mutation harness | **10,000 inputs, 0 failures** |
| External cross-check | PE section count matches `objdump -h`; import semantics documented |
| CLI contract | stdout is machine-readable JSON; gate exit codes 0/1/2 verified |
| Determinism | repeated canonical JSON is byte-identical |
| CI | pinned MoonBit `0.1.20261023`, format/check/test/native/wasm/mutation/cross-check/benchmark gates |

The xref trust boundary is explicit: only statically encoded calls that land exactly on an import slot are attributed. On `notepad.exe`, xref v2 decodes 3,285 calls, attributes 1,606 sites across 295 APIs, and keeps 1,679 unresolved direct targets visible. Indirect calls are counted, never guessed. Unsupported instruction bytes and unresolved targets remain visible in the ledger.

## Limitations

- xref v2 currently attributes only `E8 rel32` and `FF 15 rip-rel32`; other static or indirect call shapes remain unresolved.
- Linear-sweep disassembly can be misled by data interleaved with code; the ledger reports refusals instead of hiding them.
- Bundle profiling pairs a Mach-O artifact with an Info.plist; it does not unpack arbitrary `.ipa` containers.
- The policy language is intentionally small and declarative; it is not a general-purpose programming language.

# MoonForge RE Workbench（中文）

**用纯 MoonBit 做跨格式二进制证据、发布差分与 CI 门禁。**

MoonForge 把 PE / ELF / Mach-O / Info.plist / WASM 变成统一、带来源定位的事实模型，回答三个单文件解析器答不了的问题：

1. **这个 artifact 里有什么？** 格式、哈希、节、符号、导入导出、bundle 身份、WASM 节表。
2. **两个构建之间变了什么？** 确定性的 added / removed / changed 事实，带字节位置。
3. **这个版本该不该放行？** 声明式基线策略门禁，输出 JSON / SARIF 和稳定退出码。

同一份 MoonBit 核心同时驱动 native CLI 与离线 WASM 浏览器工作台；分析阶段无后端、无 FFI、无网络。

## 为什么不是“又一个解析器包装”

解析器已经存在，MoonForge 做的是**证据与决策层**：

- **证据信封**：每个 finding 带 artifact hash、parser/依赖版本、状态和字节位置。
- **xref v2**：可执行节逐节解码；`E8 rel32` 与 `FF 15 rip-rel32` 目标直接从指令字节推导，不依赖显示字符串；调用账目完整可审计。
- **统一差分**：PE / ELF / Mach-O / plist / WASM 归一化到同一 schema。
- **策略门禁**：例如“禁止新增 kernel32 导入”，输出可解释 JSON/SARIF 与稳定退出码。
- **一份核心、两种运行时**：native 与 WASM 输出来自同一份 MoonBit 代码。

## 边界

- xref v2 目前只归因 `E8 rel32` 与 `FF 15 rip-rel32`；其他静态或间接调用形态保持 unresolved。
- 线性扫描可能被代码/数据混排误导；账目会报告 refusal，而不是隐藏。
- Bundle profile 将 Mach-O 与 Info.plist 配对，不解包任意 `.ipa`。
- Policy 语言刻意保持小型声明式，不是通用编程语言。
